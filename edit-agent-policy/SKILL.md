# Edit Agent Policy
Resolve the actual project through [target resolution](../README.md#resolve-the-target). Read its instructions, policy index, exact current body and applicable adopted kernel. `ADOPT-POLICIES` owns authority and the policy/skill distinction; `PRESERVE-IDENTITY` owns continuity and dependent review. Bundled candidates are not operative project rules. This procedure adds no decision authority.

## Establish the change
Read the human's intended change, the current adopted/proposed version and useful source history. Explain what behavior or scope would change. Separate an editorial repair from a substantive change; do not label a changed obligation cosmetic. Apply the kernel's distinction to decide whether the requested correction belongs in the policy or its procedural skill.

Read the selected project’s adopted PRESERVE-IDENTITY metadata contract for fields/dates and the [format/checker notes](../review-agent-policies/references/policy-format.md) for technical representation. An authorized spelling or link repair that preserves the obligation need not manufacture a new adoption or substantive revision date.

## Prepare the amendment
1. Compare old and candidate obligations, scope and exceptions. Assess whether the same ID still expresses useful continuity. Review a type/filename change under `PRESERVE-IDENTITY`; an underscore prefix is presentation metadata, not an identity or authority change. Propose a split/new ID only when the changed meaning warrants it; coordinate [Create Agent Policy](../create-agent-policy/SKILL.md) and [Retire Agent Policy](../retire-agent-policy/SKILL.md) for those tasks.
2. Find incoming prerequisites and meaningful references, including existing skills that apply this obligation. Record how each affected dependent would change; do not redirect edges simply because the filename/ID changes.
3. For an adopted policy, prepare substantive amendments in a linked spike/change proposal or preview checkout while retaining the operative body. For a proposal, revise the candidate in place within the authorized scope. Keep the exact old/new comparison reviewable.
4. Use [Review Agent Policies](../review-agent-policies/SKILL.md), then [Adopt Agent Policies](../adopt-agent-policies/SKILL.md) for a separately requested or already-authorized adoption. An edit request that only asks for a candidate does not operate that candidate.

For a Git-backed change, hand Commit Work the affected mnemonic policy IDs and the reviewed decision rationale under PRESERVE-IDENTITY.

Report the intended difference, identity decision, affected dependents/skills and what remains operative. Preserve concurrent work and use the actual project's commit policy.
