# Adopt Agent Policies
Resolve the actual project through [target resolution](../README.md#resolve-the-target). Read its instructions, index, exact operative/candidate bodies and applicable adopted kernel. `ADOPT-POLICIES` owns decision authority, status and the policy/skill distinction; this skill supplies the adoption procedure under those obligations. The [bundled kernel](assets/kernel/policy.index.md) is candidate source, not automatically operative authority. For an initial adoption, use the actual human instruction and existing project authority rather than pretending the proposed kernel already governs.

## Prepare the exact adoption set
Identify whether the request authorizes adoption or only preparation/review. Honor an already-given decision covering the exact change; otherwise retain the candidate state and report what decision is missing. Use [Review Agent Policies](../review-agent-policies/SKILL.md) to assess the actual/candidate obligations, prerequisite set, incoming dependents, semantic conflicts and tool-enforcement boundaries. Keep the comparison concrete without treating a validator result as human agreement.

For initial kernel adoption, inspect the selected complete source/revision, then copy chosen candidates to project-owned files without replacing existing content. Record the actual source revision or content hashes in the owning proposal/spike. For later revisions, compare frozen project copies with their actual prior source and the selected new candidates, preserving local changes. Use [Edit Agent Policy](../edit-agent-policy/SKILL.md) for candidate amendments and the [migration route](references/migration.md) for legacy conversions. A collection update supplies source; it does not perform this adoption.

## Apply the authorized decision
1. Recheck current files/concurrent edits and the exact human decision against the reviewed set. Include required prerequisite/dependent changes in the same reviewed adoption set or resolve them first.
2. Apply the authorized bodies to the actual project copies and record YAML metadata, descriptive type, status, real human decision authority and substantive dates using the [shared contract](../review-agent-policies/references/policy-format.md). Do not invent a human decision record or apply a draft that the instruction did not cover.
3. Reconcile the project index using the shared tool and route AGENTS to the actual index when that routing change is included. Check the complete graph and report the resulting operative loading plan. Kernel/source copies distributed to other projects remain separate candidates.
4. Review the exact diff and any actual tool changes. Use Commit Work only under the project's commit policy; adoption does not supply publication or merge rights.

Report the adopted set, recorded authority, retained proposals, dependency impact and remaining real-use checks. Do not adopt other checkouts, install clients or change tool permissions as a side effect.
